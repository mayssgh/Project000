## 1. Task

Text-to-SQL: given a natural-language question about a small e-commerce
database (customers, products, orders, order_items), generate a SQLite
query that answers it correctly.

**Example item:**
> Question: "List the top 3 products by total quantity sold, showing product
> name and total quantity."
> Gold SQL: `SELECT p.name, SUM(oi.quantity) AS total_qty FROM order_items oi
> JOIN products p ON oi.product_id = p.product_id GROUP BY p.product_id
> ORDER BY total_qty DESC LIMIT 3;`

## 2. Data

- 50 items in `data/items.jsonl`, hand-written against a fixed schema
  (`db/schema.sql`), split 15 easy / 17 medium / 18 hard by SQL complexity
  (single-table filters → aggregations/joins → multi-join + subqueries).
- The database itself (`db/data.db`) is synthetic, generated by
  `db/seed.py` with a fixed random seed: 40 customers, 20 products,
  220 orders, ~565 order line items.
- **Label checking:** every gold SQL query is executed against the seeded
  database at build time (`data/build_items.py`) — a query that raises a
  SQL error fails the build, so every gold answer is guaranteed to be a
  real, runnable result, not just something that looked right by eye.
  [Fill in: who wrote which items, who reviewed them]
- No held-out dev/test split — all 50 items are used as the test set,
  since the assignment's purpose is a single comparative run, not model
  selection/tuning.
